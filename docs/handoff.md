# Handoff notes

This is a punch list, ordered by impact. Pick one, ship it, repeat.

## Immediate priorities

1. **Replace placeholder canvas with Konva.js.** The current
   `editor/Canvas.svelte` uses raw 2D canvas, redraws the world on
   every state change, and has no hit testing. Konva gives you a
   scene graph with persistent shapes, native drag handles, and
   `getIntersection(point)` for picking. Most editor features become
   one-liners once this is in.

2. **Wire up the remaining modes.** Bend, move, delete, and lift
   commands exist (or are easy to add) in `editor/commands/`. The
   click handlers in `Canvas.svelte` need to dispatch them. See
   `reference/iso_editor.html` for working implementations.

3. **Tests.** `core/` is pure functions. Every algorithm should have
   a Vitest spec that:
   - feeds it a fixture from `fixtures/`
   - asserts the output matches a snapshot
   - the snapshot is also generated by the Python reference
     renderer, so they stay in sync.

## High-leverage features

4. **Multi-select with marquee + bulk move.** Hold shift, drag a box,
   selected waypoints highlight. Drag any of them to move the whole
   set together. Konva's selection rectangle helper is useful here.

5. **Waypoint inspector.** When a single waypoint is selected, show
   a side panel with its grid coords, plane, and arrow-key nudging.
   Same panel for stations: name, kind, label override.

6. **Real autosave with localStorage or IndexedDB.** Write
   `mapData` to storage on every command, restore on boot. CRDT
   storage (Yjs) is overkill but futureproofs for collab.

7. **Live SVG preview pane.** A toggle that opens the rendered SVG
   alongside the editor, regenerated debounced. Helps bridge the
   gap between editing in 2.5D and shipping print artwork.

## Polish

8. **Per-plane visibility toggles.** Sometimes you want to edit just
   plane 1 without the others on screen.

9. **Color picker UI.** Currently the "swatch click for color" is
   removed from the Svelte version. Add a proper picker.

10. **Stadium markers and label placement in the live editor.**
    Currently only in SVG export. Port `core/stadium.ts` and
    `core/layout.ts` calls into the canvas renderer.

11. **Undo/redo UI.** Buttons in the toolbar, history list in a
    panel. The `history` store already has a stack.

12. **Keyboard map.** Currently `cmd+z` and `cmd+shift+z` work.
    Add tool shortcuts (`d` `b` `m` `x` `l`), plane shortcuts
    (`1` `2` `3`), and a help overlay.

## Infrastructure

13. **Storybook for `core/` algorithms.** Each algorithm gets a
    visualizer that takes input and shows output. Useful for
    debugging label placement.

14. **CI.** GitHub Actions: `npm run check`, `npm test`, `npm run
    build`. Block merges on green.

15. **Tauri shell.** Once the web version is solid, wrap it in
    Tauri for a desktop binary with native file dialogs. The
    save/load handlers in `Sidebar.svelte` need to detect Tauri
    and use its FS API instead of Blob downloads.

## Stretch

16. **Real annealing.** The current label placement does greedy
    descent. Real simulated annealing (probabilistic accept based
    on a temperature schedule) would handle pathological dense
    cases better.

17. **Auto-router.** Given a target station ABCD waypoint, compute
    the octolinear path. Like a constraint solver. Look up
    "octilinear metro map drawing" papers (Nollenburg & Wolff).

18. **Collab.** Yjs over websockets. Two people edit the same map.
    The Command pattern makes this surprisingly tractable.

## What not to do

- Don't switch to React. Svelte was deliberate; smaller bundle,
  fewer foot guns.
- Don't replace `core/` with a class hierarchy. Pure functions
  port to other languages and unit-test trivially.
- Don't skip the Command pattern. The temptation to "just mutate
  the data directly" will break undo/redo and autosave forever.
- Don't gold-plate the type system. `unknown` and explicit casts
  are fine when the alternative is six layers of generics.
